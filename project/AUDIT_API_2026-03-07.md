# API Security Audit -- 2026-03-07

## Executive Summary

Comprehensive audit of all API endpoints across 4 services: Frontend (131 routes), Admin (88 routes), PodClaw Bridge (30+ FastAPI endpoints), and MCP Server (17 tools + OAuth). The project demonstrates solid auth patterns overall -- admin uses iron-session with RBAC, frontend uses Supabase JWT auth, webhooks verify signatures. However, several **CRITICAL** findings require immediate remediation, primarily around unauthenticated RAG/test endpoints that can modify database state.

## Critical Findings

### C1: RAG Endpoints Completely Unauthenticated (CRITICAL)

**Routes:** All 17 `/api/rag/*` endpoints
**Severity:** CRITICAL
**Impact:** Any unauthenticated user can:
- Install PostgreSQL functions via `POST /api/rag/install-function` (calls `exec_sql` RPC with admin client)
- Insert arbitrary documents into the `documents` table via `POST /api/rag/add-documents` (uses `supabaseAdmin`, bypasses RLS)
- Trigger expensive Gemini API calls for embedding generation (`seed-embeddings`, `seed-products`, `seed-faqs-policies`)
- Read all RAG documents (`list-all`, `stats`)

These routes use `supabaseAdmin` (service role key, bypasses RLS) and accept unauthenticated requests.

### C2: Raw SQL Execution via /api/admin/migrate (CRITICAL)

**Route:** `POST /api/admin/migrate`
**Severity:** CRITICAL
**Mitigation present:** Requires `requireAdmin`, blocked in production unless `ALLOW_ADMIN_MIGRATE=true`
**Risk:** Accepts raw SQL in request body and passes it to `supabaseAdmin.rpc('query', { query_text: sql })`. If the `query` RPC exists in the database, this is a full SQL injection vector for any admin user. No input sanitization, no allowlisting.

### C3: test-db-schema Endpoint Exposes DB Schema + Writes Test Data (CRITICAL)

**Route:** `GET /api/test-db-schema`
**Severity:** CRITICAL
**Impact:** Unauthenticated endpoint that:
- Queries table structure using service role key
- **Inserts and deletes test records** in production tables (`processed_events`, `cron_runs`, `returns`, `orders`)
- Modifies order refund columns (`stripe_refund_id`, `refund_amount_cents`) with test data
- Allowlisted to 4 tables but still writes to production data

### C4: verify-schema Endpoint Exposes DB Information Schema (CRITICAL)

**Route:** `GET /api/verify-schema`
**Severity:** CRITICAL
**Impact:** Unauthenticated endpoint that queries `information_schema.columns` using service role key and returns full column details for any public table (table name comes from query param).

### C5: PodClaw Bridge Auth Disabled by Default

**Config:** `BRIDGE_AUTH_ENABLED=false` (default)
**Severity:** HIGH
**Impact:** All 30+ Bridge endpoints (task execution, agent control, stop/start, soul modification) are accessible without authentication when auth is not explicitly enabled. Additionally, localhost IPs are always exempt even when auth is enabled.

### C6: Newsletter test-drip Triggers Real Email Sends Without Auth (CRITICAL)

**Route:** `POST /api/newsletter/test-drip`
**Severity:** CRITICAL
**Impact:** Unauthenticated POST endpoint that triggers drip email sequences. Can be abused to send emails and consume Resend API credits.

## Additional Findings (WARN)

### W1: No Rate Limiting on Several Mutating Frontend Routes

The following authenticated POST/PATCH/DELETE routes lack rate limiting:
- Cart operations (POST/PATCH/DELETE `/api/cart`)
- Newsletter subscribe (`POST /api/newsletter/subscribe`)
- Error report (`POST /api/errors/report`)
- Profile export (`GET /api/profile/export`)
- Shipping estimate (`POST /api/cart/shipping-estimate`)

### W2: Design Compose/Remove-bg Routes Lack Authentication

`POST /api/designs/compose`, `POST /api/designs/compose-v2`, `POST /api/designs/remove-bg` accept unauthenticated requests and can trigger external API calls (background removal service).

### W3: Multiple Test/Debug Endpoints in Production

~15 test endpoints under `/api/newsletter/test-*`, `/api/telegram/test-*`, `/api/marketing/test-*` are deployed without environment guards. Some are guarded by `NODE_ENV === 'production'` checks (A/B test routes) but most newsletter test routes are not.

### W4: Admin Metrics Endpoint Unauthenticated

`GET /panel/api/metrics` (admin) and `GET /api/metrics` (frontend) expose Prometheus metrics (memory usage, uptime, environment info) without authentication.

### W5: /api/chat Route Has Optional Auth But Triggers Expensive AI Calls

The main chat endpoint accepts requests with optional authentication and can trigger AI model calls, Supabase queries, and tool executions. No rate limiting is applied.

### W6: /memory/context/{file} -- Potential Path Traversal

PodClaw Bridge's `/memory/context/{file}` reads files by name. Without path sanitization, could potentially read files outside the intended directory. Needs verification of path validation in the handler.

### W7: PodClaw Bridge CORS Too Permissive

CORS middleware uses `allow_methods=["*"]` and `allow_headers=["*"]`. Should be restricted to specific methods and headers needed by the admin dashboard.

## Recommendations (Priority-Ordered)

### P0 -- Immediate (Block Deployment)

1. **Add auth to ALL RAG endpoints.** Use `requireAdmin` for seed/install/index operations. Consider removing them entirely from production builds.

2. **Remove or disable `test-db-schema` and `verify-schema` endpoints.** They should never be accessible in production. Guard with `NODE_ENV !== 'production'` at minimum, or delete them.

3. **Remove all `/api/newsletter/test-*` endpoints** from production, or guard with `NODE_ENV` check + admin auth.

4. **Enable PodClaw Bridge auth by default.** Change `BRIDGE_AUTH_ENABLED` default to `true`. The current default of `false` means any misconfigured deployment exposes full agent control.

### P1 -- High Priority (This Sprint)

5. **Add parameterized query validation to `/api/admin/migrate`.** Even though it requires admin auth, raw SQL execution is inherently dangerous. Consider removing the RPC call entirely and using only Supabase migrations.

6. **Add rate limiting to unauthenticated design endpoints** (`compose`, `compose-v2`, `remove-bg`).

7. **Add authentication to `/api/designs/compose*` and `/api/designs/remove-bg`** -- these trigger external API calls.

8. **Add rate limiting to the chat route** (`POST /api/chat`) to prevent AI cost abuse.

9. **Restrict PodClaw Bridge CORS** to specific methods and headers instead of wildcards.

### P2 -- Medium Priority (Next Sprint)

10. **Add rate limiting to cart operations** and other unauthenticated mutating routes.

11. **Add auth to admin metrics endpoints** or restrict to internal networks only.

12. **Validate `file` parameter in PodClaw Bridge `/memory/context/{file}`** to prevent path traversal.

13. **Add `Cache-Control: no-store` headers** to authenticated API responses that return sensitive data (profile, orders, payment methods).

14. **Add Zod validation** to all POST/PATCH routes that currently use manual `body.field` validation without schema enforcement.

### P3 -- Low Priority (Backlog)

15. **Consolidate admin auth patterns.** The admin app uses three different auth approaches: `withAuth` (auth-middleware.ts), `requireAuth` (auth.ts), and `getAdminSession` (rbac.ts). Consolidate to a single pattern for maintainability.

16. **Add request logging/audit for frontend API routes.** Admin routes have audit logging via `withAuth`; frontend routes do not.

17. **Add idempotency keys to webhook handlers** (Stripe webhook already checks signature but lacks explicit replay protection beyond Stripe's built-in dedup).
