### Feature #175: Hybrid search combines vector + keyword ✅

**Implementation**:
- Created `hybrid_search_documents()` RPC function in PostgreSQL
- Combines 70% vector similarity + 30% keyword text matching (PostgreSQL `ts_rank`)
- Returns `similarity`, `text_rank`, and `hybrid_score` for each result
- Updated `/api/rag/search` to use hybrid search instead of pure vector
- Fixed return types (`source_id: text` not `uuid`, to match `VARCHAR(255)` schema)

**Search Algorithm**:
```sql
hybrid_score = 0.7 * vector_similarity + 0.3 * text_rank

vector_similarity = 1 - (embedding <=> query_embedding)  -- cosine similarity
text_rank = ts_rank(to_tsvector('english', content), plainto_tsquery('english', query_text))
```

**Verification**:
```bash
# Test 1: General query
curl -X POST http://localhost:3000/api/rag/search -d '{"query":"cat t-shirt","limit":3}'
→ ✅ Top result: "Classic Cat T-Shirt"
   - similarity: 0.7198 (semantic match)
   - text_rank: 0.6772 (keyword match)
   - hybrid_score: 0.707 (0.7 * 0.7198 + 0.3 * 0.6772)

# Test 2: Specific product name
curl -X POST http://localhost:3000/api/rag/search -d '{"query":"Classic Cat T-Shirt","limit":5}'
→ ✅ Top result: "Classic Cat T-Shirt" (exact match)
   - similarity: 0.8036 (high semantic match)
   - text_rank: 0.7911 (high keyword match)
   - hybrid_score: 0.7998 (0.7 * 0.8036 + 0.3 * 0.7911)
```

**Benefits**:
- Exact product names rank higher (text matching boosts them)
- Semantically similar products still appear (vector similarity)
- Better than pure vector search for precise product name queries
- Better than pure keyword search for understanding intent
